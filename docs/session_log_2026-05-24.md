## Architecture decisions worth preserving

**CV embed pipeline (the one tricky integration today):**
- `cv.qmd` uses a raw HTML block `` ```{=html} `` containing the wrapper `<div class="cv-embed"><!-- CV_CONTENT --></div>`. Pandoc-flavored markdown comments inside fenced divs can get stripped during rendering — the raw HTML block is the reliable way to guarantee the marker survives.
- The embed script targets the `<main>` element specifically (not `<body>`), because Quarto wraps standalone HTML output in additional chrome (`<body>` includes nav, footer, etc.) that we don't want to inject.
- Strip `#title-block-header` from the CV content before injecting — its ID would collide with the website's own title block on the host page (invalid HTML).
- All CV styles live in `styles.scss` under a `.cv-embed { ... }` block; this scoping prevents CV-specific rules (h2 underlines, body width caps, scholar-stats panel styling) from bleeding out to the rest of the site.

**Author parsing in `parse_authors()`:**
- The CV-style author strings have commas INSIDE each author (`Lastname, F. I.`) AND BETWEEN authors. Naive `split(", ")` breaks every author into two pieces.
- Solution: regex-match each author chunk with `\\*?[A-Z][A-Za-z'\\-]+,\\s+[A-Z]\\.(?:\\s*[A-Z]\\.)*` rather than splitting. Each match is one author; we then reverse "Lastname, F. I." to "F. I. Lastname".
- Edge cases handled: leading `*` (student involvement marker), hyphenated last names (`Eleuterio-da-Rocha`), apostrophes (`O'Brien`), single-initial names (`Johncox, J.`), multi-initial names (`Tanksley, P. T.`).

**JSON-LD output strategy:**
- One `<script type="application/ld+json">` per page, containing a `@graph` array of all articles. Google accepts and prefers this over multiple small script tags.
- Hunter's author object includes `url` + `sameAs` (ORCID) — these are the entity-resolution anchors that bind the article authorship to the home page Person entity. Without them, Google sees "an author named Martaindale" rather than "Hunter Martaindale who lives at huntermartaindale.com".
